# Power BI report: start here

## Open the finished project (about 2 minutes)

The report is already built as a **Power BI Project** (`council-spending.pbip`): a 14-table star-schema model, 36 DAX measures, relationships, a theme and 5 report pages (67 visuals). It was opened in Power BI Desktop (v2.158), refreshed, and its headline numbers were checked against the SQL results.

1. Install Power BI Desktop (free, Windows).
2. Open **`powerbi/council-spending.pbip`** (double-click it, or File > Open). `data/processed/` is already included, so you do not need to run Python.
3. The data location is stored in a parameter. If the report shows no data or an error, point it at your copy of the data:
   **Home > Transform data > Edit parameters > DataFolder** = the full path to the `data\processed\` folder **including the trailing backslash**, for example `C:\Users\you\council-spending-dashboard\data\processed\`. Then click **Home > Refresh**.
   If Power BI says *"There are pending changes in your queries"*, click **Apply changes**.
4. **File > Save as** `council-spending-dashboard.pbix`. This gives one portable file that contains the data.
5. Sanity-check the Overview cards: net spend **£347.8M**, payment lines **37,261**, named suppliers **2,645**.

Screenshots of all five pages are in [`docs/images/`](../docs/images) (`dashboard_*.png`).

| Page | What it shows |
|---|---|
| Overview | Slicers (financial year, month, expenditure type, directorate), 6 KPI cards, monthly spend by theme, spend by directorate and theme, month-on-month change |
| Suppliers | Top-10 share, tail spend (suppliers paid in one month only), Pareto of the top 15 suppliers, spend by supplier type, ranked supplier table, new suppliers by month |
| Categories | Directorate x theme matrix, treemap of categories, service areas, capital vs revenue vs HRA, purpose of payment |
| Data quality | 22-check scorecard (colour-coded), % affected, review lists for possible duplicate payments, reused supplier IDs and multi-ID suppliers |
| Classification | Text-classification agreement, confusion matrix (council theme vs model theme), coding-review queue |

## How the project is built
Everything is generated by [`build_project.py`](build_project.py) (`python powerbi/build_project.py --data-folder "<path>\"`), so the layout, measures and relationships are reproducible and reviewable as plain text. `02_measures.dax` is generated from the same measure list and is there for reading.

## Known limitations
* Numbers display with your Windows regional digit grouping (for example lakh grouping on an en-IN machine).
* Long directorate and supplier names are truncated in some charts (hover for the full name).
* The binary `.pbix` is not committed (it embeds the data); create it with step 4.
